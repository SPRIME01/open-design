# Domain Vocabulary & Concepts

This document defines the formal vocabulary and domain models of Open Design. It clarifies what each term means, what it specifically does *not* mean when ambiguity might arise, how it connects to adjacent concepts, and where it is declared in the implementation.

---

## 1. Compiler Domain Concepts

### Application IR
- **What it means**: A framework-agnostic, versioned semantic intermediate representation defining an entire application: domain models (entities, types), capabilities (commands, queries, events), API boundaries (transports, auth), persistence (tables, migrations), and frontend nodes (screens, components, flows).
- **What it does NOT mean**: It is not raw AST for TypeScript or JavaScript, nor is it a simple JSON configuration or template dump.
- **Relationships**: Authored in `application.ir.json` (or modular `ir/*.ir.json` files); validated by `@open-design/application-ir`; consumed by `@open-design/application-compiler`.
- **Implementation**: [`packages/application-ir/src/schemas/`](file:///home/sprime01/projects/open-design/packages/application-ir/src/schemas/) (`ApplicationIRBundleSchema`).

### Target Adapter
- **What it means**: A compiler backend adapter implementing the `ApplicationTargetAdapter` interface. It accepts a lowered IR AST and emits concrete, framework-native files for a specific stack (e.g. `react-vite`, `nextjs-app`, `sveltekit`, `sqlite-better-sqlite3`).
- **What it does NOT mean**: It is not an AI prompt template or LLM generation wrapper; target adapters are pure deterministic code emitters.
- **Relationships**: Registered in `adapterRegistry`; invoked during Pass 6 (`project`) of the compilation pipeline.
- **Implementation**: [`packages/application-compiler/src/adapter-contract.ts`](file:///home/sprime01/projects/open-design/packages/application-compiler/src/adapter-contract.ts), [`packages/application-targets/src/`](file:///home/sprime01/projects/open-design/packages/application-targets/src/).

### Compile Plan (`CompilePlan`)
- **What it means**: A deterministic description of planned filesystem modifications. It classifies every target file as `create`, `modify`, `reuse`, or `conflict`, computes a cryptographic `planHash`, and models permissions and diagnostic warnings before disk writes occur.
- **What it does NOT mean**: It is not an in-flight execution thread or background job; it is a previewable changeset data structure.
- **Relationships**: Produced by `prepareAdapterPlan()` and `planApplication()`; can be approved via `POST /api/compiler/runs/:id/approve` using its `planHash`.
- **Implementation**: [`packages/application-compiler/src/plan.ts`](file:///home/sprime01/projects/open-design/packages/application-compiler/src/plan.ts) (`CompilePlan`).

### Generated Manifest (`GeneratedFileManifest`)
- **What it means**: A persistent cryptographic inventory stored in `compiler/manifests/` that tracks every file generated by the compiler along with its content hash, source IR node IDs, and adapter versions.
- **What it does NOT mean**: It is not an arbitrary package lockfile or build artifact directory list; it is an ownership and change-attribution record.
- **Relationships**: Used during subsequent compile runs to detect whether a user has manually modified a generated file.
- **Implementation**: [`packages/application-compiler/src/manifest.ts`](file:///home/sprime01/projects/open-design/packages/application-compiler/src/manifest.ts) (`GeneratedFileManifest`).

### Conflict Policy (`ConflictResolution`)
- **What it means**: The deterministic policy applied when a file on disk has been hand-edited since it was last generated. Supported policies:
  - `block` (default): Aborts compilation immediately with status `conflicted` without modifying disk.
  - `plan-only` (retain-manual): Emits non-conflicting files while excluding conflicting files from the write set and manifest.
  - `force`: Overwrites hand-edited files to reclaim compiler ownership (only legal when explicitly requested).
- **What it does NOT mean**: It is not a 3-way git merge; Open Design never silently merges or corrupts manual edits.
- **Relationships**: Configured in `projection.config.json` per target or passed as an explicit CLI flag (`--conflict-resolution`).
- **Implementation**: [`packages/application-compiler/src/conflict.ts`](file:///home/sprime01/projects/open-design/packages/application-compiler/src/conflict.ts) (`ConflictResolution`).

### Lowering Pass
- **What it means**: An atomic transformation step in the 9-pass compiler pipeline that refines high-level semantic nodes into lower-level representations or validates invariants.
- **What it does NOT mean**: It is not an external shell script or build command.
- **Relationships**: Executed in strict sequence: `resolve` -> `normalize` -> `domainCheck` -> `capabilityCheck` -> `frontendLowering` -> `componentLowering` -> `atomicValidation` -> `platformLowering` -> `targetPlanning`.
- **Implementation**: [`packages/application-compiler/src/pipeline.ts`](file:///home/sprime01/projects/open-design/packages/application-compiler/src/pipeline.ts) (`orderedLoweringPasses`).

## 2. Agent Runtime & Studio Concepts

### RuntimeAgentDef
- **What it means**: A typed declaration defining how Open Design discovers, probes, spawns, and parses an external coding agent CLI (e.g. `claude`, `codex`, `opencode`, `cursor-agent`, `deepseek`, `devin`).
- **What it does NOT mean**: It is not an agent itself; it is the host adapter specification.
- **Relationships**: Registered in `apps/daemon/src/runtimes/defs/`; probed concurrently during startup by `detectAvailableAgents()`.
- **Implementation**: [`apps/daemon/src/runtimes/types.ts`](file:///home/sprime01/projects/open-design/apps/daemon/src/runtimes/types.ts) (`RuntimeAgentDef`).

### Physical Run
- **What it means**: A managed in-memory entity representing a single execution turn of an agent subprocess or compilation job, tracking PID trees, start time, telemetry lineage, and terminal status (`succeeded`, `failed`, `canceled`).
- **What it does NOT mean**: It is not a persistent database row for an entire conversation; conversations consist of multiple sequential runs.
- **Relationships**: Must be started through `internalRunCreation.start()`; tracks process teardown in `apps/daemon/src/runtimes/runs.ts`.
- **Implementation**: [`apps/daemon/src/runtimes/runs.ts`](file:///home/sprime01/projects/open-design/apps/daemon/src/runtimes/runs.ts), [`apps/daemon/src/services/internal-run-service.ts`](file:///home/sprime01/projects/open-design/apps/daemon/src/services/internal-run-service.ts).

### `<question-form>` Artifact
- **What it means**: A structured markdown artifact emitted inline by an AI agent when human intent is underspecified or requires design confirmation. The web UI renders this artifact as an interactive form and returns answers in the next turn.
- **What it does NOT mean**: It is not a stdin tool-call prompt or modal alert; it is rendered inline in the chat flow.
- **Relationships**: Generated by the agent; detected by `AssistantMessage.tsx`; formatted back via `POST /api/chat`.
- **Implementation**: [`apps/web/src/artifacts/question-form.ts`](file:///home/sprime01/projects/open-design/apps/web/src/artifacts/question-form.ts), [`apps/daemon/src/question-form-detect.ts`](file:///home/sprime01/projects/open-design/apps/daemon/src/question-form-detect.ts).

### Run Steering
- **What it means**: The capability for a user to inject further instructions into an agent process that is actively executing (`POST /api/runs/:id/steer`).
- **What it does NOT mean**: It does not kill and restart the process; it streams input directly into the running process's stdin.
- **Relationships**: Supported only on agents with `promptInputFormat: 'stream-json'` (such as Claude Code).
- **Implementation**: [`apps/daemon/src/runtimes/run-steering.ts`](file:///home/sprime01/projects/open-design/apps/daemon/src/runtimes/run-steering.ts).

## 3. Architecture & Infrastructure Concepts

### Sidecar Stamp
- **What it means**: An immutable 5-tuple (`channel`, `namespace`, `source`, `mode`, `app`) passed via CLI arguments (`--od-stamp-*`) that uniquely identifies a sidecar process.
- **What it does NOT mean**: It is not a port, process PID, or filesystem path.
- **Relationships**: Consumed by `@open-design/sidecar` to compute principal-scoped, hashed Unix domain sockets or named pipes for IPC.
- **Implementation**: [`packages/sidecar/src/`](file:///home/sprime01/projects/open-design/packages/sidecar/src/) (`SidecarStamp`).

### Daemon Data Directory (`RUNTIME_DATA_DIR`)
- **What it means**: The single source of truth for all daemon-managed persistent data (SQLite database, managed projects, artifacts, plugin states, credentials).
- **What it does NOT mean**: It is not an arbitrary working directory or user-chosen path.
- **Relationships**: Resolved once upon daemon startup from `OD_DATA_DIR`; all internal paths (`PROJECTS_DIR`, `ARTIFACTS_DIR`) derive strictly from it.
- **Implementation**: [`apps/daemon/src/daemon-paths.ts`](file:///home/sprime01/projects/open-design/apps/daemon/src/daemon-paths.ts).

### UI/CLI Dual-Track
- **What it means**: The mandatory architectural rule that every user-facing capability must be reachable both through the Web UI and the `od` CLI, backed by the identical daemon HTTP endpoints and contracts in `packages/contracts`.
- **What it does NOT mean**: It does not mean the CLI is a thin wrapper that scrapes the web frontend; both talk directly to `/api/*`.
- **Relationships**: Enforced by repo guard and PR guidelines; registered in `SUBCOMMAND_MAP` in `apps/daemon/src/cli.ts`.
- **Implementation**: [`apps/daemon/src/cli.ts`](file:///home/sprime01/projects/open-design/apps/daemon/src/cli.ts).

### Brand Design System
- **What it means**: A directory in `design-systems/<brand>/` containing `DESIGN.md` (guidelines), `tokens.css` (color and spacing CSS custom properties), and `components.html` (interactive HTML component fixtures).
- **What it does NOT mean**: It is not an npm dependency or external design kit; it is local, file-based design intelligence.
- **Relationships**: Injected into agent prompts during creative generation runs.
- **Implementation**: [`design-systems/`](file:///home/sprime01/projects/open-design/design-systems/), guarded by [`scripts/guard.ts`](file:///home/sprime01/projects/open-design/scripts/guard.ts).

### Universal Craft Rules
- **What it means**: Brand-agnostic design heuristics in `craft/` covering universal quality concerns such as accessibility, animation discipline, anti-ai-slop, and state coverage.
- **What it does NOT mean**: They are not specific to any one brand or design system.
- **Relationships**: Opted into by skills via `od.craft.requires` in `SKILL.md`.
- **Implementation**: [`craft/`](file:///home/sprime01/projects/open-design/craft/), validated by [`scripts/lint-craft-references.ts`](file:///home/sprime01/projects/open-design/scripts/lint-craft-references.ts).
