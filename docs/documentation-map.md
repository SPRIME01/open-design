# Documentation Map

This document is the master navigational index for the Open Design technical knowledge system. It classifies every document by its [Diátaxis](https://diataxis.fr/) quadrant (Tutorial, How-To Guide, Reference, Explanation), declares its primary audience need, maps prerequisite reading paths, and provides contextual cross-links.

---

## 1. Intent-Based Navigation Paths

Choose a reading path tailored to your immediate goal:

### Path A: Learn the System (Newcomer / Architecture Exploration)
If you are new to the repository or seeking to understand how the components fit together:
1. [Orientation & System Identity](file:///home/sprime01/projects/open-design/docs/orientation.md) — 5-minute plain-language foundation, problem statement, and system overview diagram.
2. [Mental Model](file:///home/sprime01/projects/open-design/docs/mental-model.md) — The dual-engine architecture: Creative Studio Loop vs. Application Compiler Pipeline.
3. [Domain Vocabulary & Concepts](file:///home/sprime01/projects/open-design/docs/concepts.md) — Key terms and mental models specific to Open Design.
4. [Architecture Overview](file:///home/sprime01/projects/open-design/docs/architecture.md) — Canonical high-level structural, process, and security topology.
5. [Subsystems Directory](file:///home/sprime01/projects/open-design/docs/subsystems/) — Deep dives into Daemon, Web, Compiler, Agent Runtimes, and Sidecars.

### Path B: Get Something Done (Hands-On Implementation)
If you need to produce working software or extend capabilities immediately:
- **Build an App from IR**: Follow the tutorial [Building Your First App from IR](file:///home/sprime01/projects/open-design/docs/tutorials/build-first-app-from-ir.md).
- **Run a Design Studio Generation**: Follow [First Studio Generation](file:///home/sprime01/projects/open-design/docs/tutorials/first-studio-generation.md).
- **Add a New AI Agent CLI**: Follow [How to Add an Agent Adapter](file:///home/sprime01/projects/open-design/docs/how-to/add-agent-adapter.md).
- **Add a Compiler Target**: Follow [How to Add a Compiler Target](file:///home/sprime01/projects/open-design/docs/how-to/add-compiler-target.md).
- **Add a Brand Design System**: Follow [How to Add a Design System](file:///home/sprime01/projects/open-design/docs/how-to/add-design-system.md).
- **Run Packaged Smoke Tests**: Follow [How to Run Packaged Smoke Tests](file:///home/sprime01/projects/open-design/docs/how-to/run-packaged-smoke-tests.md).

### Path C: Understand "Why" (Design Rationale & Decisions)
If you need to understand the constraints and non-obvious choices behind the architecture:
- [Why UI and CLI Dual-Track?](file:///home/sprime01/projects/open-design/docs/explanations/dual-track-interface.md) — The embeddability contract and single-source HTTP API design.
- [Why a 9-Pass Compiler?](file:///home/sprime01/projects/open-design/docs/explanations/nine-pass-compiler.md) — Determinism, AST lowering, conflict preservation, and verifiability.
- [Why Two Prompt Implementations?](file:///home/sprime01/projects/open-design/docs/explanations/prompt-composition-split.md) — Legacy slim/classic vs. OD Next scenario plugin strategy.
- [Why 5-Field Sidecar Stamps?](file:///home/sprime01/projects/open-design/docs/explanations/sidecar-process-stamps.md) — Process isolation, opaque private IPC, and zero port dependence.
- [Why the Strict Daemon Data Directory Contract?](file:///home/sprime01/projects/open-design/docs/explanations/daemon-data-directory-contract.md) — Data isolation, managed vs. external workspace security boundaries.

### Path D: Follow Execution Workflows (Runtime Tracing)
If you are debugging or tracing runtime execution end-to-end:
- [Application Compilation Workflow](file:///home/sprime01/projects/open-design/docs/workflows/application-compilation.md) — `od app compile` / `/api/compiler/runs` through lowering, planning, write, and verify.
- [Creative Generation Lifecycle](file:///home/sprime01/projects/open-design/docs/workflows/generation-lifecycle.md) — `/api/chat` prompt composition, CLI child process spawn, SSE streaming, and preview.
- [User Clarification Workflow](file:///home/sprime01/projects/open-design/docs/workflows/user-clarification.md) — `<question-form>` inline artifact generation, UI rendering, and continuation.
- [Local Development Lifecycle](file:///home/sprime01/projects/open-design/docs/workflows/local-dev-lifecycle.md) — `pnpm tools-dev start` sidecar orchestration and readiness.

### Path E: Look Something Up (Technical Reference)
If you need exact signatures, schemas, commands, or flags:
- [CLI Reference](file:///home/sprime01/projects/open-design/docs/reference/cli.md) — Complete specification of `od` subcommands.
- [REST API & SSE Reference](file:///home/sprime01/projects/open-design/docs/reference/api-and-sse.md) — HTTP routes, SSE events, and DTO contracts.
- [Application IR Schema Reference](file:///home/sprime01/projects/open-design/docs/reference/ir-schema.md) — `application.ir.json` Zod specifications.
- [Environment Variables & Ports](file:///home/sprime01/projects/open-design/docs/reference/environment-and-ports.md) — Configuration keys, ports, and default paths.
- [Troubleshooting & Diagnostics](file:///home/sprime01/projects/open-design/docs/troubleshooting.md) — Diagnostic matrix and error recovery paths.
- [Source Traceability Map](file:///home/sprime01/projects/open-design/docs/source-map.md) — Cross-index connecting concepts to source code files and symbols.
